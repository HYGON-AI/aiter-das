# Custom ReduceScatter：INT8 / FP8

`CustomAllreduce.reduce_scatter` 和 `custom_reduce_scatter` 支持连续的 FP32、FP16、BF16、INT8，以及 E4M3FN、E5M2。Hygon 通信接口不支持两个 FNUZ 类型。

## 数值合同

执行跨 rank 的 **SUM**，再沿指定维度按组内 rank 顺序均分。输入、输出必须同 dtype；无隐式 scale、反量化或动态量化。

| 输入/输出 | 累加与存储 |
| --- | --- |
| INT8 | INT32 累加，最后保留低 8 位，按有符号 INT8 解释；溢出回绕，不饱和。例如 TP2 的 `100 + 100` 得到 `-56` |
| E4M3FN / E5M2 | 按具体格式解码到 FP32，按源 rank 升序累加，最后一次 RNE 转回原格式；转换非饱和，跨架构保持一致 |
| FP32/FP16/BF16 | 保持原有实现和数值约定 |

FP8 的 E4M3FN 越界可产生 NaN；E5M2 可产生 Inf。保留子正规数；NaN 的分类有保证，payload/sign 不作合同。该算子处理 FP8 本身表示的数值；若输入是外部量化数据，调用方负责统一各 rank 的 scale。它不能直接实现不同 scale 的量化 SUM。

FP8 转换采用固定非饱和合同，正确性参考使用独立格式查表与 RNE；环境中的饱和 cast 不能直接作为该数值合同的参考。

这与 [AllGather](custom_all_gather.md) 的按位复制不同：ReduceScatter 不能把 FP8 编码当 UINT8 数值相加。实现虽使用 UINT8 视图传递指针，但 native 收到独立格式码并执行真实数值规约。通信和 staging 每元素仍为 1 byte，没有先把整个输入展开成 FP32 后通信。

## 使用

构造 `ca` 的方式见 [通信接口说明](communication_ops.md)。所有 rank 须以相同次序调用 collective，并使用一致 shape/dtype/dim。

```python
# x: contiguous INT8 or FP8 GPU tensor; split_dim is divisible by TP size
dim = -1
shape = list(x.shape)
shape[dim] //= ca.world_size
y = torch.empty(shape, dtype=x.dtype, device=x.device)
if not ca.should_custom_rs(x, dim):
    raise ValueError("input is outside the custom ReduceScatter contract")
ca.reduce_scatter(x, y, dim)  # writes y, returns None
# Or: ca.custom_reduce_scatter(x, y, dim)
```

- 支持 TP2/4/8、首维/中间维/末维和负维度；分片维必须整除 TP，Tensor ABI 最多 8 维。
- 输入总字节数整除 16；首维分片的每 rank 输出也必须满足 16B 长度对齐。末/中维不能向量化时使用 scalar kernel。
- 输出连续、shape/dtype/device 匹配、地址 16B 对齐且不与输入重叠。copy-in 可接受连续但地址不对齐的输入。输出地址检查也适用于既有 FP16/BF16/FP32 和 scalar 路径：不对齐的切片输出现在明确报错，调用者应提供对齐的输出缓冲区。
- 大小限制沿用 `should_custom_rs`：不超过 `min(_LEGACY_AR_MAX_SIZE, max_size // 2)`，并满足设备、拓扑与通信组准入。
- `reduce_scatter` 拒绝不支持的输入时抛异常。`custom_reduce_scatter` 拒绝时返回 `None`、不写输出；成功时也返回 `None`，不能用返回值判定是否执行。
- DTK 下保留 copy-in。`registered=True` 或请求 Graph 注册不表示实际直接注册，必须检查有效注册策略；当前不宣称直接输入注册验证通过。
- `CudaCommunicator.reduce_scatter` 命中 custom 准入时可使用这些 dtype。FP8 超出 custom 准入或 custom 通信器不可用时明确抛出 `ValueError`，不执行 RCCL FP8 SUM；FNUZ 始终拒绝。INT8 保留原生 RCCL SUM 回退；回退通信器缺失或已禁用时抛出 `RuntimeError`，不会返回未写入的输出。

底层 `aiter.ops.custom_all_reduce.reduce_scatter` 保持原五参数首维 ABI；`reduce_scatter_dim` 保持维度参数 ABI，增加 INT8/E4M3FN 分派。这里的 `AITER_DTYPE_fp8` 仅表示 E4M3FN；直接传入 E5M2 Tensor 会在 launch 前拒绝。E5M2 必须使用类方法，或内部 `reduce_scatter_8bit` 的 UINT8 views 加明确格式码（INT8=0、E4M3FN=1、E5M2=3；其他格式码不支持），不得将 E5M2 存储伪装为 E4M3FN 描述符。UINT8 数值 SUM 不在当前公开支持范围内。

## 验证与性能复现

```bash
# 默认先运行全部 dtype 正确性，再测 INT8/E4M3FN 性能。
torchrun --nnodes=1 --master_addr=127.0.0.1 --master_port=29672 --nproc_per_node=4 \
  op_tests/multigpu_tests/test_custom_reducescatter.py \
  --bench --repeats 20 --rounds 9 --iters 30 --output rs_bench_tp4
```

默认性能 size 为每 rank 的 `256,4096,8192,32768,262144,1048576,4194304` bytes。INT8/FP8 每元素 1 byte，8192 bytes 即 8192 元素，输出为 `8192/TP` 元素。只测该 size 可添加 `--sizes 8192`；正确性包含 `[16,512]` 首维/末维及变化输入 Graph。去掉 `--bench` 可仅检查正确性，无需初始化 RCCL。

专用正确性覆盖支持的 dtype、首/中/末维、向量/标量路径、20 次变化输入 Graph、立即输入复用、全部 65,536 对 INT8/FP8 字节编码、公共 communicator、底层 ABI 与异常准入。

增加 `--check-fallback` 可验证 INT8 溢出和 FP32 的 RCCL 首/中/末维 eager/Graph 回退，以及 FP8 拒收和无可用后端的异常合同；该选项会初始化 RCCL。CI 与专用测试共享独立 FP8 oracle，INT8 参考显式执行 INT32 累加和模 256。

Eager 绑定合同可单独复现（在相同环境运行）：

```bash
torchrun --nnodes=1 --master_addr=127.0.0.1 --master_port=29673 --nproc_per_node=4 \
  op_tests/multigpu_tests/test_custom_collective_eager.py --output collective_eager_tp4
```

此测试检查原转换回退、Eager直接调用、原生Tensor绑定三条路径的存储/shape/偏移变化与交替stream，并执行fullgraph/Inductor回归。直接注册AG在DTK上只验证导出图；公开注册接口仍按能力回退copy-in。

## 最终性能对比（2026-10-14，Eager优化后）

Eager入口保留参数校验和copy-in/sync，省去torch.ops/dummy分派，并通过通信专用绑定逐次读取Tensor元数据。不缓存Tensor裸指针或stream；低层入口的torch.compile路径继续使用注册的算子。旧native缺少新绑定时回退到原有描述符转换。

当前代码的 gfx936 TP2/4/8、gfx938 TP2/4 均通过正确性和性能验证；INT8/E4M3FN 各测 7 个输入 size，包含 8192 bytes，首维/末维、eager/Graph，共 280 行。E5M2 通过正确性验证，未单独测量性能。gfx938 TP8 暂无 RCCL 对照结果。

环境：单机 IPC、GPU 0..TP-1，gfx936 Torch 2.11.0、gfx938 Torch 2.10.0；HIP 6.3.26113、DTK 26.04、RCCL 2.22.3。每项 9 轮、每轮 30 次，GPU event 计时，每轮取跨 rank 最大值，再取中位数；custom 包含 copy-in 与同步。未锁频。

RS 输入 shape 为 `[16, bytes/16]`，输出元素数为输入的 `1/TP`。custom 为预分配输出的 `reduce_scatter`。INT8 对照原生 RCCL INT8 SUM；**FP8 对照“转 FP32 → RCCL FP32 SUM → 转回 FP8”，包含必要重排，不是原生 RCCL FP8。**

表中单位为 **μs**，每格为 **custom / 对照** 延迟，越小越快；加速比等于对照除以 custom。`*` 表示其中任一路的 9 轮样本 CV>10%，仍保留该结果。8192 行加粗标出。

custom/对照路径中，58/280 行存在 CV>10% 的波动。Graph 在图内串联 30 次 collective；eager 区间包含 CPU 提交间隙，二者不能混用或外推为模型吞吐。
