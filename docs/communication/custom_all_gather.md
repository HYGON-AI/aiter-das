# Custom AllGather

`CustomAllreduce.custom_all_gather` 将各 rank 的输入按组内 rank 顺序拼接，并在每个 rank 返回相同结果。传输保留原始位，不进行规约、量化或反量化。

## 类型和形状

| 项目 | custom 路径合同 |
| --- | --- |
| dtype | FP32、FP16、BF16、INT16、INT32、INT64、INT8、UINT8；FP8 仅 `float8_e4m3fn`、`float8_e5m2` |
| 输入 | 当前设备上 1–8 维的非空连续张量，所有 rank 的 shape/dtype 一致 |
| 维度 | 首维 `dim=0`，或末维 `dim=-1` / 正索引；输出该维度扩大 TP 倍 |
| 对齐 | 总输入字节数是 16 的倍数；末维 gather 每行字节数也是 16 的倍数；显式输出指针 16 字节对齐 |
| 容量 | 每 rank 输入不超过 `max_size / (2 * TP)`；`max_size` 是通信器配置的 staging 容量 |
| 卡数 | TP2、TP4、TP8，并通过现有 IPC 拓扑准入 |
| 输出 | 与输入 dtype/device 相同，连续，不得与输入重叠 |

Hygon 通信接口不支持两个 FNUZ 类型。FP8 在 AG 边界被解释为 UINT8 存储，输出恢复原 dtype。NaN、Inf、正负零等编码按位保留；是否存在这些特殊值由具体格式决定。该通信不要求 FP8 算术指令。量化 scale 如需通信，应由调用者另外收集并保持对应的 rank/布局顺序。

首维 gather 只要求总字节数对齐，例如 INT8 `[16,3]` 可以走 custom。相同输入进行末维 gather 因行长 3 字节而不适用。

显式输出的 16B 地址检查同样适用于既有 FP16/BF16/FP32 等类型；不对齐的切片输出会报错。copy-in 输入仍可使用连续但地址不对齐的存储。

## 使用方式

已经创建 `CustomAllreduce` 通信器时：

```python
import torch

x = torch.randint(-128, 128, (32, 4096), device="cuda", dtype=torch.int8)
y = ca.custom_all_gather(x, dim=-1)  # [32, TP * 4096], int8
if y is None:
    # 低层接口用 None 表示不满足 custom 条件，调用者负责选择后端。
    ...

# 可提供输出缓冲区，避免 eager 重复分配。
out = torch.empty((32, ca.world_size * 4096), device=x.device, dtype=x.dtype)
ca.all_gather_unreg(x, out=out, dim=-1)  # 返回同一个 out

# 用原始编码演示 FP8 传输；这一步只是位视图，不是量化。
raw = torch.arange(256, device="cuda", dtype=torch.int64).to(torch.uint8).reshape(8, 32)
x_fp8 = raw.view(torch.float8_e4m3fn)
y_fp8 = ca.custom_all_gather(x_fp8, dim=-1)  # [8, TP * 32]，dtype 不变
# 实际推理可直接传已量化的 FP8 Tensor；scale 由调用方另行管理。
```

已初始化 AITER 模型并行组时，公开接口负责回退：

```python
from aiter.dist.communication_op import tensor_model_parallel_all_gather

y = tensor_model_parallel_all_gather(x, use_custom=True, dim=-1)
```

自定义组使用 `aiter.dist.communication_op.custom_all_gather(x, use_custom=True, dim=-1, group="name")`。组的创建方式见 [通信接口总览](communication_ops.md)。

公开接口在首维/末维满足条件时直接调用对应 custom kernel；不满足时使用现有 RCCL/PyTorch 路径。FP8 回退同样以 UINT8 传输和重排，最后恢复 dtype。`use_custom=False` 也支持这个 FP8 回退。其他维度仍由回退路径处理。

## Graph 与同步

```python
with ca.capture():
    warm = ca.custom_all_gather(x, dim=-1)
    graph = torch.cuda.CUDAGraph()
    with torch.cuda.graph(graph):
        y = ca.custom_all_gather(x, dim=-1)

# 在同一 stream 上更新 x 后重放；每次输入可以变化。
x.copy_(next_x)
graph.replay()
```

gfx936/gfx938 的 DTK 路径保留预注册 staging 的 copy-in 与 AG 结束同步。请求 `enable_register_for_capturing=True` 不代表实际采用直接注册。不要绕过该策略或去掉结束同步。各 rank 必须以相同顺序调用 collective。

## 验证与性能复现

```bash
# 需相应数量的空闲可见 GPU；先构建候选 module_custom_all_reduce。
torchrun --nnodes=1 --master_addr=127.0.0.1 --master_port=29671 --nproc_per_node=4 \
  op_tests/multigpu_tests/test_custom_allgather.py \
  --mode correctness --repeats 20 --output ag_correctness_tp4

torchrun --nnodes=1 --master_addr=127.0.0.1 --master_port=29671 --nproc_per_node=4 \
  op_tests/multigpu_tests/test_custom_allgather.py \
  --mode all --dtypes int8,float8_e4m3fn --rounds 9 --iters 30 --max-size-mib 128 \
  --output ag_bench_tp4
```

每个 rank 输出独立 JSON，记录 Torch/HIP、RCCL、架构、实际注册策略、加载的 native 路径与 SHA256。性能按相同 payload 比较，包含 custom copy-in/同步及各自末维重排，采用 GPU event 和跨 rank 最大值；同时报告公开 API 与旧首维后重排策略。Graph 一次捕获 30 次通信、每轮 replay 后除以 30；eager 连续调用 30 次，其 event 区间包含 CPU 提交间隙。原始轮次、median、P95、CV 全部保留。

`op_tests/ci_tests/test_custom_allreduce_api.py --suite collectives` 已纳入新类型、全部 256 字节编码与 Graph 输入立即复用；默认 TP2/TP4 的 CI 启动策略不变，TP8 显式运行。

默认性能 size 为每 rank 的 `256,4096,8192,32768,262144,1048576,4194304` bytes。INT8/FP8 每元素 1 byte，8192 bytes 即 8192 元素。只测该 size 可添加 `--sizes 8192`；正确性包含 `[8,1024]` 首维/末维及变化输入 Graph。

Eager 绑定合同可单独复现（在相同环境运行）：

```bash
torchrun --nnodes=1 --master_addr=127.0.0.1 --master_port=29673 --nproc_per_node=4 \
  op_tests/multigpu_tests/test_custom_collective_eager.py --output collective_eager_tp4
```

此测试检查原转换回退、Eager直接调用、原生Tensor绑定三条路径的存储/shape/偏移变化与交替stream，并执行fullgraph/Inductor回归。直接注册AG在DTK上只验证导出图；公开注册接口仍按能力回退copy-in。

## 最终性能对比（2026-10-14，Eager优化后）

Eager入口保留参数校验和copy-in/sync，省去torch.ops/dummy分派，并通过通信专用绑定逐次读取Tensor元数据。不缓存Tensor裸指针或stream；低层入口的torch.compile路径继续使用注册的算子。旧native缺少新绑定时回退到原有描述符转换。

当前代码的 gfx936 TP2/4/8、gfx938 TP2/4 均通过正确性和性能验证；INT8/E4M3FN 各测 7 个输入 size，包含 8192 bytes，首维/末维、eager/Graph，共 280 行。E5M2 通过正确性验证，未单独测量性能。gfx938 TP8 暂无 RCCL 对照结果。

环境：单机 IPC、GPU 0..TP-1，gfx936 Torch 2.11.0、gfx938 Torch 2.10.0；HIP 6.3.26113、DTK 26.04、RCCL 2.22.3。每项 9 轮、每轮 30 次，GPU event 计时，每轮取跨 rank 最大值，再取中位数；custom 包含 copy-in 与同步。未锁频。

AG 输入 shape 为 `[8, bytes/8]`，输出元素数为输入的 TP 倍。custom 为预分配输出的 `all_gather_unreg`；RCCL 按 UINT8 传输，末维包含必要重排。

表中单位为 **μs**，每格为 **custom / 对照** 延迟，越小越快；加速比等于对照除以 custom。`*` 表示其中任一路的 9 轮样本 CV>10%，仍保留该结果。8192 行加粗标出。

custom/对照路径中，49/280 行存在 CV>10% 的波动。Graph 在图内串联 30 次 collective；eager 区间包含 CPU 提交间隙，二者不能混用或外推为模型吞吐。
