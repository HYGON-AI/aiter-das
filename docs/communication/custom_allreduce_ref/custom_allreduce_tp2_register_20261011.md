# HCU TP2 寄存器规约性能（2026-10-11）

[返回最新用法与性能](../custom_allreduce.md)

gfx936/gfx938 单机 IPC 的普通 TP2 传统路径复用已有寄存器 one-stage kernel，
每线程读取两路16B pack，按 rank 0、1 顺序执行FP32累加并按RNE写回。使用256线程，
保留原grid、staging copy-in、start/end_sync及DTK版本相关launch策略。默认off也适用。
FP16/BF16/FP32支持范围不变；Fabric、其他rank/架构、旧算法和注册输出分派保持原行为。

## 方法

与P1本卡输入优化版本进行同机同卡ABBA。每批30个样本，Graph每样本32次调用，
每个样本先取各rank最大值；表格为两轮中位数的均值，单位μs。RCCL包含clone。
gfx936：BW200 / UBB BW1000，80 CU；gfx938：BW1100，72 CU。测试使用TP2、单机IPC、RCCL自动拓扑和默认协议；gfx938为共享GPU环境。
完整对照统计与原始样本一起单独归档，不随源码分发。

## 精度与适用范围

最终版本在两架构的FP32 FTZ/RNE、有序求和、边界、布局与连续复用检查通过；
普通CAR和fused AR RMS回归结果见[组合结果](custom_allreduce_optimized_20261011.md)。
精度参考保持既有FP32 FTZ与RNE，不代表完整IEEE渐进下溢。

实际ISA显示TP2使用已有寄存器device函数，减少相对旧LDS版本的LDS和私有存储访问；
FP32顺序、BF16 RNE、copy-in与同步均保留。资源差异不等于PMC证明的瓶颈归因。

未覆盖跨节点Fabric、rank6/16/32/40硬件运行和其他架构。大载荷仍有staging成本，
不能外推为所有TP或载荷均大幅领先RCCL。未采用的调优方案保留在外层试验记录。
