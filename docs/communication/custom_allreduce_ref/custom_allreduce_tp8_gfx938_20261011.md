# gfx938 CustomAllreduce TP8 性能结果（2026-10-11）

[返回最新用法与性能](../custom_allreduce.md)

架构gfx938，BW1100，72 CU，8张GPU，单机IPC。Torch 2.11.0 / HIP 6.3.26113。
共享GPU环境，有其他计算/显存占用；结果不代表独占性能。
比较版本为`892b5d9c`与旧基线`9fb16b23`。本表采用历史auto范围；当前TP8 auto使用传统路径，见[组合结果](custom_allreduce_optimized_20261011.md)。

## 结果解读

- 八卡精度和接口回归通过；本轮没有证明TP8 LL稳定提速，默认继续off。BF16 Graph 4KiB的off/LL为19.140/25.387μs，CV为4.79%/5.60%，本次LL中位时延高32.64%。64KiB LL也更慢且波动很大，不能据此设定稳定回退阈值。
- 旧基线到候选off的表面降幅为39.73%–81.82%，但旧基线开测前卡1计算利用率为100%，各组占用不同；该降幅不能作为源码优化的稳定收益。相同传统回退在256KiB、896KiB、8MiB等处也出现明显时段差异。
- 32MiB BF16 Graph候选off为644.270μs，RCCL+clone为533.432μs，本次CAR中位数高20.78%；CAR CV为66.15%。大载荷性能差距仍未闭合。
- two-stage的2MiB、+64B和+128B分别确认优化完整tile、naive和优化partial-tile分派；本次off中位数为51.365、62.802、52.027μs。精度通过不意味着任意partial tile都采用同一kernel或具有相同时延。
- 历史使用说明是TP2数据，不能与本TP8表直接比较。此前双架构小载荷算法对照仍单独保留。

## 测量口径

每组30样本，Graph每样本32次操作，每次样本取8个rank的最大时延。Graph列采用GPU-event，eager列采用CPU wall time；单位μs。
不含初始化、编译和Graph构建；包含每次执行中的copy-in及kernel同步。
CAR为未量化、out-of-place SUM；RCCL对照包含clone。保留Graph copy-in、BF16 RNE与同步保护。
旧基线只运行合法完整tile；候选覆盖阈值两侧和partial tile。首轮off与末尾off对照分别列出，不择优替换。
TP8使用`dyadic_tp8_v2`精确输入：八元素周期值/8 + rank/8 + refresh/4，refresh为0..4；任意rank子集的和均可精确表示，CAR与RCCL都使用零容差检查。TP2/TP4沿用原输入。
全部760组通过计时前后和同地址输入更新检查，每组8×30个GPU及wall原始样本均保留。
按展示指标统计，Graph GPU-event CV>10%为153/380组，eager wall CV>10%为309/380组。
全部GPU-event统计中CV>10%为 485/760（包含eager的GPU-event）。`*` 表示该表采用指标的CV>10%。

## 精度与覆盖

- 17个回归job通过；普通CAR 32用例，fused/split AR RMS 96路径用例。
- 四模式混合Graph边界共 61440 次精确输出检查；reuse共 614400 次精确输出检查，零错。另有强抵消、容量/配置/能力回退、collectives/fusions/transport和MHC共享模块回归。
- 原CI最大error_ratio：CAR `0.011579240672290325`，RMS `0.0`；均遵守原门限。容差统计与精确输出检查分别记录。
- Graph trace单独运行并排除于正式30样本性能表；核实copy-in、LL及传统回退、完整tile与partial-tile路径。
- 128份独立Graph trace验证实际分派，trace不计入正式性能样本。
- 本轮仅增补gfx938 TP8；双架构TP2/TP4结果见[此前算法结果](custom_allreduce_hcu_algorithms_20261010.md)。
- 未覆盖真实跨节点Fabric、6/16/32/40 rank硬件运行、其他架构专用路径、完整模型精度及长期稳定性。

完整FP16/BF16/FP32统计、CV/P95/max、首尾off比值和trace汇总，与原始失败、每rank样本及构建来源证据一起单独归档，不随源码分发。
