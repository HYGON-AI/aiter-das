# HCU CustomAllreduce 组合优化结果（2026-10-11）

[返回最新用法与性能](../custom_allreduce.md)

主要收益集中在TP2，以及TP2/4的小载荷Graph；eager和TP8不保证提速。
gfx938部分批次出现显著延迟跳变，本文保留较慢结果及其统计，不能按正常批次替换。

组合实现包含LL/LL128本卡原输入读取、HCU IPC TP2寄存器规约和保守的auto策略。
默认off使用传统路径，其中TP2采用256线程寄存器one-stage；auto仅在TP2/4、
FP16/BF16、输入≤32KiB时选择LL，其余使用传统路径。显式ll/ll128协议上限保持。
两架构分别编译和验证，实测后采用相同准入策略。

生产源码提交为`7e3361d8`，源码与实测版本一致。

## 对照方法

基线e525ba10与组合候选按旧off/新off/新auto/新auto/新off/旧off顺序运行。
普通CAR使用`use_new=True`、`open_fp8_quant=False`，未开启不安全的Graph输入直接注册。
每架构1872行，FP16/BF16、TP2/4/8、13个输入尺寸、Graph/eager及CAR/RCCL+clone。
每行30个原始样本；Graph每样本32次调用，逐样本取各rank最大值。下表为配对批次
中位数的均值，单位μs；完整机器可读统计单独归档，不随源码分发。
所有失败、长尾和原始样本保留。RCCL包含clone，不能与裸RCCL kernel混为同一口径。

gfx936：BW200 / UBB BW1000，80 CU；gfx938：BW1100，72 CU。TP2/4/8分别使用2/4/8张GPU，单机IPC；gfx938为共享GPU环境，不代表独占性能。全部对照使用RCCL自动拓扑和默认协议。

## 精度与来源验证

每架构2520组rank-case、22680次RNE/抵消/Inf-NaN/subnormal/guard精度输出通过；
P1 off、组合off、组合auto的Graph输出位摘要一致（NaN payload归一化）。另有127680次边界、
8064次布局、3024次有序求和和1075200次连续复用输出零错。参考模拟既有FP32 FTZ
和RNE模式，没有更改浮点选项；完整IEEE渐进下溢不属于本实现的保证范围。

每架构完成普通CAR 96项、fused/split AR RMS 288路径项。
普通CAR原CI以输入dtype逐次执行`ref += x`作为参考；其error_ratio表示不满足
`atol=rtol=0.01`的元素比例，沿用门限0.03。这不同于FP32累加后RNE的专项参考，
也不是候选相对旧基线的输出差异比例。两类精度证据分别记录。

共享API另外覆盖TP2/4/8的AG/RS、
融合RMS/量化/QK、transport契约和MHC回归。每个进程核验实际Python路径与native SHA。
CAR、MHC与RMS使用相容的已核验实现。

每架构588份主trace和588份预热trace验证实际路由：自动LL为零前置DtoD，
传统回退保留copy-in，TP2传统调用寄存器kernel。CAR ELF全部525个device函数
与P1指令文本完全一致；BF16 RNE、FP32累加、epoch/ack/fence/end_sync未删减。
共享设备结构、class字段以及IPC/Fabric/supernode扩展保持。

## 范围与限制

收益随TP、载荷和架构变化，32MiB仍包含安全staging成本，不保证普遍大幅领先RCCL。
TP8 auto使用传统路径，未证明小载荷LL在TP8稳定胜出。

未覆盖完整模型精度和吞吐、跨节点Fabric、rank6/16/32/40硬件运行、其他架构及FP32
延迟矩阵。共享GPU环境存在干扰，不能把未归因的波动直接解释为代码优化。
