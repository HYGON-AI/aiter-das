# HCU LL 本卡输入优化结果（2026-10-11）

[返回最新用法与性能](../custom_allreduce.md)

LL/LL128 直接读取本卡输入并向既有通信 scratch 发布数据，省去一次前置 D2D。
传统规约仍使用安全 staging；不启用任意 cached 输入的跨卡直接注册。输入与输出
必须均为16B对齐且不重叠，容量与量化路径检查保持有效；否则保留 copy-in。

## 测量方法

基线为`e525ba10`，优化版本为`19156e7e`。
同机同卡执行 baseline/candidate/candidate/baseline，各行保留30个原始样本；
Graph 每样本32次调用，先取同次样本各rank最大值，再计算统计量。下表为
两轮基线中位数的均值与两轮候选中位数的均值，单位 μs；不是混合样本的中位数。
RCCL 对照包含 clone。完整统计含 FP16/BF16、Graph/eager、TP2/4/8，
与原始样本和失败记录一起单独归档，不随源码分发。

gfx936：BW200 / UBB BW1000，80 CU；gfx938：BW1100，72 CU。测试使用TP2/4/8、单机IPC；gfx938为共享GPU环境。每个A/B子矩阵使用相同拓扑和协议配置，跨TP数据不用于隔离比较配置收益。

## 精度与适用范围

gfx936有3456行完整ABBA结果，gfx938有3008行。gfx938未完成TP8 ll128重复回退组的完整ABBA，因此不纳入其性能结论；TP8 off的传统路径对照完整。

每架构完成107,520次混合尺寸边界输出、8,064次布局/别名输出、3,024次有序求和
输出，以及1,075,200次连续复用输出检查，精确比较零错。覆盖FP16/BF16/FP32、
off/ll/ll128/auto、输入更新、交错Graph、慢rank及通信器重建。

每架构504份主trace及504份预热trace核验通过：准入LL/LL128为零前置DtoD，
传统回退保留DtoD。60个相关device函数的完整指令文本与基线一致，FP32累加、
BF16 RNE、release/acquire、消费ack及end_sync未删除。epoch使用uncached分配，共享设备结构及主机类字段未改变。

这项修改优化已准入的算法，不意味着所有载荷都应走LL：TP4较大LL及TP2较大
LL128仍可能慢于传统路径，TP8也未得到普遍胜出的结果。当前默认仍为off，
使用`AITER_AR_SMALL_MESSAGE=ll/ll128/auto`时才可能省去copy-in。
TP8的ll128请求仍使用传统回退。当前阈值和组合性能见[最终结果](custom_allreduce_optimized_20261011.md)。

未覆盖完整模型精度、跨节点Fabric、rank 6/16/32/40硬件运行和其他GPU架构。
本表不替代最终普通CAR及fused AR RMS回归结果。
